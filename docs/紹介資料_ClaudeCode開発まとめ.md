# Claude Codeで作った「生産管理 × お客様向けWebツール」開発まとめ

*プリント・刺繍加工業の現場から生まれた自社開発システム「HiBoard」紹介資料(ブログ・WEB掲載用ドラフト)*

---

## 1. はじめに — どんな会社が、なぜ作ったか

- 衣類へのプリント・刺繍加工、サッカー特化のウェア・ユニフォーム企画製作、自社ブランドの小売を手がける町工場
- 案件の受付〜生産〜納品の管理が、電話・LINE・紙・記憶に分散していた
- 外注開発ではなく、**社長自身がAIコーディングツール「Claude Code」を使って内製**
- 結果: **約5週間・126コミット**で、社内の生産管理から「お客様が実際に使う公開ツール」までを一気通貫で構築

**技術構成(シンプルさ重視)**
- Node.js / Express + SQLite(better-sqlite3)
- 社内のWindows機1台で稼働、Cloudflare Tunnel経由で必要なページだけ外部公開
- サーバー費用ゼロ・月額課金ゼロで運用

---

## 2. 社内向け — 生産管理システム「HiBoard」

### 2-1. 案件管理(かんばん・一覧)
- 受付日・納期・加工種別・数量・担当者・ステータスを一元管理
- ステータス: 受注前 → 確定 → 準備 → 進行中 → 検品 → 納品待ち → 完了
- 案件ごとの「準備項目」チェックリスト(デザインデータ作成・作業指示書など)を全社共通のマスタで管理

### 2-2. 週間スケジュールボード
- 従業員×日付のマス目に作業をドラッグ&ドロップで割り当て
- 案件の見込み時間から**1日の負荷を自動集計**、入れすぎが一目でわかる
- 祝日・個人ごとの勤務パターン・臨時の稼働変更(終日不可/時間指定)にも対応
- 担当者未定の案件を拾い上げる「提案確認パネル」で割り当て漏れを防止

### 2-3. 納品履歴と「再注文」ワンクリック複製
- 過去案件を顧客名・案件名で検索
- リピート案件は「↻ 再注文」ボタンで品目・プリント位置ごと複製 → 入力の手間ほぼゼロ

### 2-4. 受注候補ボックス(すべての注文の合流地点)
- LINE・Webフォーム・チーム注文・取引先依頼——**どの経路から来た注文も1つの「受注候補」一覧に着地**
- 受付番号で経路がわかる(W-=Web / T-=チーム / P-=取引先 / LINE)
- 新しい受注候補が着地すると、**社員のTODOリスト(Googleスプレッドシート)へ自動でタスク追記** → 対応漏れ防止

### 2-5. 社員向け使い方ガイド(/manual)
- 業務フロー順の7章構成マニュアルをアプリ内に同梱
- ブラウザ印刷でそのままA4配布資料になる印刷用CSS付き

## 3. お客様向け — 公開Webツール

### 3-1. Web注文フォーム(/order)
- 3つの依頼モードをタブで切替:
  1. **かんたん相談**(連絡先+希望時間帯+自由記述だけ。電話ヒアリング前提の最少入力)
  2. **見積・イメージ依頼**
  3. **正式発注**
- 送信すると受付番号(W-番号)を発行し、**受付控えメールを自動送信**
- 入力途中の内容はブラウザに24時間自動保存(誤って閉じても復元)
- スマホ写真(HEIC形式)の添付にも対応

### 3-2. ご注文の流れガイド(/guide)
- 注文〜納品までのステップを整理した案内ページ(明朝見出し×生成り白の落ち着いたデザイン)
- QRコード付きA4印刷用PDFも用意し、店頭・同梱チラシとして配布

### 3-3. 注文進捗確認ページ(/status)
- **受付番号+電話番号下4桁**だけで、お客様が自分の注文の進行状況を確認できる
- ステータスはお客様向けに4段階へ簡略化(受付済み/製作中/検品・出荷準備中/納品済み)
- 総当たりアクセス対策のレート制限など、セキュリティにも配慮

## 4. チーム向け — 追加注文フォーム(専用URL方式)

- 提携しているクラブチームごとに**専用URL(トークン付き)を発行**
- チームの担当者はそのURLを開くだけで、名前×背番号×サイズ×枚数の行入力で追加注文できる
- サイズ展開(110〜160/S〜XXL)はチームごと・アイテムごとに設定可能
- 参考単価・参考合計を自動表示(正式金額は受付後に案内する運用)
- 管理画面からURLの発行・編集・無効化/再有効化がワンクリック

**→ 「LINEで枚数とサイズを聞き直す」やり取りが専用フォームに置き換わった**

---

## 5. 取引先(BtoB)向け — 納期確認ポータル&加工依頼フォーム

### 5-1. 納期確認ポータル(/partner/専用URL)
- 取引先が**自社案件の進行状況・納品予定日をいつでも閲覧**できる専用ページ(閲覧専用)
- 「上がりはいつ?」の電話問い合わせ削減が狙い
- 案件との紐付けは顧客名パターンで自動判定、ステータスは取引先向け4段階に丸めて表示

### 5-2. 持ち込み加工依頼フォーム
- 同じ専用URLから、持ち込み品の加工依頼をWebで送信できる
- 持ち込み予定日・指図書番号・品物ごとの加工内容(方法×箇所×内容×色を複数登録可)・画像添付に対応
- 加工方法はプルダウン選択(シルク/DTF/ラバー/刺繍/帽子刺繍 ほか)
- 送信内容はそのまま受注候補(P-番号)に着地し、社員TODOにも自動通知

**→ 将来的には「案件入力を取引先側にしてもらう」受発注のDXへ**

---

## 6. リモートスタッフ向け — デザイナー用マイスケジュールボード

- リモート勤務のデザイン担当者が使う専用URL(/designer/専用URL)
- 自分の担当タスクを週間カレンダーで表示し、**ドラッグ&ドロップで作業日を自分で決められる**(スマホはタップ操作)
- 見込み時間の入力・完了操作・稼働申告(この日は終日不可/○時間だけ可)も本人から申告できる
- **社内の週間ボードと同じデータを共有**——社内・本人どちらから予定を入れても二重管理にならない
- デザイン系の準備項目(データ作成・指示書・見積書など)は案件登録時に**自動でデザイン担当へ割り当て**
- 社員TODOリスト(スプレッドシート)の本人分タスクもボードに自動表示し、日付に配置可能

**→ 「納期共有が口頭・チャット頼み」だったリモート協業が、1枚のボードに集約された**

---

## 7. LINE経由の注文もAIが下処理

- お客様からのLINEメッセージを**AIが自動で解析し、注文情報(顧客名・内容・数量など)を抽出**して受注候補に登録
- 人間は「候補を確認して案件化する」だけ。転記作業がなくなった

---

## 8. 番外編 — 選手応援 特設ページ&グッズ販売

- 所属選手の応援Tシャツ販売用に、**専用ドメインの特設ページ**を構築(黒基調のランディングページ)
- カラー切替タブ(BLACK/WHITE)・前面/背面ギャラリー・販売価格/締切/選手還元の明示
- 決済はネットショップ(BASE)の商品ページへ誘導する分担設計
- 2件目以降も使い回せる共通テンプレート設計 → **「特設サイト+応援グッズ販売」のパッケージ商品化構想へ**
- SNS告知画像(フィード用4:5・ストーリー用)もHTML+ヘッドレスブラウザで自動生成

## 9. 運用・インフラの工夫(ここもClaude Codeで構築)

| 項目 | 内容 |
|---|---|
| 外部公開 | Cloudflare Tunnel経由。固定IP不要・ポート開放不要 |
| 公開範囲の制御 | 公開ドメインでは注文フォーム等の公開ページのみ許可、社内画面は遮断(外部公開ガード) |
| 本番反映 | 本番機で `update.bat` をダブルクリックするだけ(取得→依存更新→再起動を自動実行) |
| 常駐運用 | タスクスケジューラでサーバーが落ちても5秒後に自動復活 |
| バックアップ | DBを毎日自動バックアップ(30世代)+NASへ二重保存 |
| セキュリティ | 進捗照会のレート制限、トークン式専用URL、エラー詳細の非表示化 など |

---

## 10. Claude Codeでの開発スタイル(内製がうまく回った理由)

1. **調査 → 方針提示 → 承認 → 実装**の順を毎回徹底(いきなりコードを書かせない)
2. 実装後は開発機で動作確認し、スクリーンショット付きで報告させる
3. 開発ルール・本番反映手順を `CLAUDE.md` に明文化 → AIが毎回同じ手順を守る
4. 本番反映は「コミット承認 → 本番機でバッチ実行」の固定フローで事故防止
5. 毎週月曜の社員向け「社内システムお知らせ」(A4)も、**git履歴からClaude Codeが自動生成**(カスタムスキル化)
