## B. ビジュアルの統一(継ぎ足し感の解消)

### B-1. デザイントークンを新設
- **`public/styles/tokens.css`** を新規作成し、色・余白(4pxグリッド)・文字サイズ・角丸・影・重なり順・フォーカスリングをここだけで定義。
- main.css は先頭で `@import url('tokens.css')` するため、main.css を読む全画面に自動で行き渡る。main.css を使わない画面(designer-board / order-status / partner-status / order.css)にも個別に読み込ませた。
- グレーは Tailwind gray の1系統に統一(slate系129箇所と works-add 独自rampを廃止)。
- `--secondary-color` と `--success-color` の同値重複を解消。
- 旧名 `--border-radius` / `--box-shadow` は別名として残してあるので、既存の参照は壊れない。

### B-2. ヘッダーとナビゲーション
- ヘッダーの中身を **`public/js/ui.js` が `data-nav` 属性から生成**。11画面のコピペを解消し、どの画面からでも他画面へ直接移動できるようになった(以前は原則トップ経由)。
- 表に出すのは日常業務の4つ(スケジュール / 納品履歴 / 顧客台帳 / 使い方)。設定・発行系6つは **「⚙ 管理」メニュー**に格納。
- 表示中の画面は `aria-current="page"` で白く反転し、押しても遷移しない。
- スマホ幅ではナビを畳み **「☰ メニュー」** で開閉。
- 同義の絵文字(`✕`と`×`、`✎`と`✏`、`🔍`と`🔎`)を整理。閉じるボタンは ui.js が `✕` に統一する。

### B-3. 部品の統一
- ボタン: `btn` + `btn-{primary|secondary|danger|danger-soft|ghost}` + `btn-small` の1系統に整理。
  - 「無効にする」など取り消せる注意操作には、一覧で騒がしくならない `btn-danger-soft` を用意。
  - 行削除のアイコンボタンは `.btn-icon-remove` に分離(モーダルの `.btn-close` と混同していた)。
- バッジ/ピル/チップは共通ルールにまとめ、角丸をピル型に統一(以前は5種)。
- 「有効/無効」の2実装(`.active-badge` と `.status-pill`)を同じ配色に統合。
- カード/白い箱を1レシピに統合。
- 空状態は `.empty-notice`(旧 `.folder-notice` は別名として維持)、読み込み中は `.folder-loading` にスピナー付きで統一。
- リンク管理3画面の三重コピペCSS(`.link-url` `.status-pill` `.size-pills` `.base-warning` ほか)を main.css へ集約。

## C. 操作性の改善

### C-1. モーダルの共通化(`js/ui.js`)
- **Esc キーで閉じる**(全モーダル。以前は0件)
- **背景クリックで閉じる**(以前は5個が未対応)
- `role="dialog"` / `aria-modal` / `aria-labelledby` を自動付与
- 開いたら最初の入力欄へフォーカス、閉じたら**元のボタンへフォーカスを戻す**
- Tab キーをモーダル内に閉じ込める(フォーカストラップ)
- 各画面の閉じる処理を活かすため、閉じる時はヘッダーの `.btn-close` を実際にクリックする方式。JS生成モーダル(案件フォルダ閲覧・案件詳細)にも `MutationObserver` で同じ挙動が効く。
- 各画面に散っていた背景クリック処理(6箇所)を削除して ui.js に集約。
- 送信ボタンには自動フォーカスしない(Enter連打での誤送信を避けるため)。

### C-2. 新規案件モーダルの再構成
- **入力順に5セクションへ分割**(基本情報 / 加工内容 / 準備と担当 / データと書類 / 作業内容・メモ)。`<details>` なので開閉はキーボードでも操作できる。
- 「データと書類」は使うときだけ開けばよいので既定で閉じる。**必須項目は必ず開いたセクションに置く**(閉じた `details` の中の `required` はブラウザ検証でフォーカスできず、送信が無言で止まるため)。
- **保存ボタンをモーダル下端に固定**。`form` 属性でフォームに紐づけているので、作業計画セクションまでスクロールしても押せる。
- **削除ボタンを左端に離した**(以前は保存の隣で誤クリックの危険)。スケジュールボードの勤務時間編集も同じ配置に統一。
- **紛らわしい時間入力2欄に説明を付けた**: 作業予定時間(分)=ボードに置くときの目安 / 見積もり工数(時間)=見積書用の控え、スケジュール計算には使わない。
- **「必要スキル」を英語コードの手入力からチェックボックスへ**。placeholder が `SILK_SCREEN,DTF` だったが、実際に突き合わせるのは加工種別のコード(`SILK_SCREEN_PRINT` 等)で、**書いてある通りに入力しても一致しなかった**。受注候補の確定画面も同じ形式に揃えた。

### C-3. 一覧ビュー
- 納期の状態を**文字でも併記**(「納期超過」「3日以内」「7日以内」のバッジ)。行の背景色は淡くし、左端に色帯を追加。色の意味は凡例を表示。
- **並び替えできる列だけを押せる見た目に**(以前は81個のthが押せそうに見えて押せなかった)。並び替え中の列は ▲▼ と `aria-sort` で示す。
- 操作ボタン3個を1行に収め、行の高さを揃えた。

### C-4. フィードバックの統一
- `alert()` 93回を**トースト通知**に置換。画面をブロックせず、メッセージ内容から成功/エラー/注意を自動判定して色分けする。
- 「通知のあとに画面を再読み込みする」処理でも消えないよう、表示予定時刻を `sessionStorage` に持たせて読み込み後に続きを表示する。
- 破壊的操作の `confirm()` は**あえて残した**。ドラッグ&ドロップ中など同期的に真偽値が必要な箇所があり、非同期ダイアログへの置換は制御フローの書き換えを伴ってリスクが高い。ネイティブの confirm はキーボード操作可能で誤操作もしにくいため、現状で妥当と判断。
- 英語のサーバーエラー文(`Project not found`)が画面に出ていた箇所を日本語の説明に置換。

### C-5. カレンダービュー
- 列幅を7等分に固定(以前は案件のある曜日だけ広がっていた)。
- 案件バーの色を**ステータス連動**に(以前は全部同じ青)。今日のセルに枠を表示。

### C-6. モバイル/タブレット
- トップの絞り込みを**スマホでは畳む**ようにし、1画面目に案件が1件も見えなかった状態を解消(現在は3件見える)。
- ヘッダーを「☰ メニュー」に格納。
- ブレークポイントを社内画面で3つに統一(767 / 768〜1180 / 480)。`designer-board` の逆方向(mobile-first 760px)も揃えた。
- `schedule-board.css` に2つあった同一条件の `@media (max-width:767px)` を1つに統合。
- main.css 末尾でメディアクエリ圏外に追記されていた116行を、適切なセクションへ移した。
- `prefers-reduced-motion` に対応。

### C-7. アクセシビリティ
- `<label for>` を付与。単一の入力に紐づかない見出しは `<label>` をやめて `.form-label` に変更(読み上げの対応先がない誤案内を解消)。
- `:focus-visible` を1ルールで全体に適用。青いヘッダー上では白いリングに切り替える。
- 絵文字だけのボタンに `aria-label`。タブに `role="tablist"` / `aria-selected`。
- チェックボックス群を `fieldset` + `legend` に。

### C-8. 用語の整理
- 「担当者管理」と「従業員管理」が別概念のまま並んで区別がつかなかったので、**担当者マスタ(案件の窓口)** / **従業員マスタ(作業する人)** と役割を併記。各画面にも1行の説明を追加。
- タブ名「コピペ取り込み」→**「受注候補の取り込み」**(開発機能名ではなく業務の入り口の名前に)。
- `/manual` の該当箇所と Q&A も更新済み。

## 本番反映

本番機で `update.bat` をダブルクリックすると反映される。
静的ファイルは Cache-Control: no-cache なのでブラウザは開き直すだけでよい(ハードリフレッシュ不要)。

DBスキーマの変更は無いので、マイグレーションや設定(.env)の追加作業は不要。

## 今後この設計を崩さないために

画面を追加・改修するときのルールは **`CLAUDE.md` の「画面を作るときのルール」** に集約した。
トークン(`styles/tokens.css`)と共通部品(`js/ui.js`)を使わずに独自実装を足すと、
今回解消した「継ぎ足し感」が同じ形で戻る。
