## 受付と案件の流れ(2026-09-02 MTG決定)

**一次受付は三浦さんに集約する。公式LINE・メール・電話はすべて三浦さんが最初に見て、電話も三浦さんが出る。**
(以前「公式LINEは全部山本さんが確認」という運用にしていたが、山本さんはEC・サンプル作り・写真撮影で時間を取られ即レスが担保できないため、三浦さんの一次受付に戻した)

- 三浦さんが中身を見て仕分ける
  - **サッカー関連** → 三浦さんがそのまま進行する
  - **それ以外** → 山本さんへ振る
- 山本さんや鈴木さんが進行する案件も、**指示書と見積書は三浦さんに提出される**。三浦さんはそれを受けてボディを発注し、生産ラインに乗せる
- 案件情報は最終的にすべて三浦さんに集まる形にする

鈴木さん(デザイン担当)に個人的なつながりで注文が入った場合、鈴木さんはその場で山本さんへ引き継ぐ。

- **サッカー関連の打ち合わせには山本さんを同席させる。** 指示書・見積書に起こしやすくなるのと、三浦さんの接客・話し方を学ばせる育成目的。**将来は山本さん1人で打ち合わせできる状態を目指す**
- 企業紹介などサッカー以外の打ち合わせは山本さんは不参加

### 土日祝の対応ルール

- 全員休みのため、**気づいた人が「週明けに連絡します」とだけ返信する**(三浦さん・山本さん・鈴木さん・久保田の4人全員が対象)
- **その場で内容には答えない**(定休日である旨を伝えるだけ)
- 対応が必要なものは **Googleチャットで三浦さんに集約**する。「この連絡が来たので公式ラインを確認してください」という形で連絡が来るので、週明けに三浦さんが公式LINEを確認して対応する

## 行動ルール

- **秘密情報を読み取り・出力しない** — `.env` / `credentials` / `.pem` / `.key` / APIキー / トークン等の機密ファイルや値は、読み込みも出力も行わない
- **本番機の `db/projects.db` と `.env` には絶対に触れない・読まない** — 顧客データとSMTP認証情報が入っている
- **個人情報を不必要に書き出さない** — マイナンバー、口座番号、生年月日、住所等はレスポンスに含めない
- **顧客データをログ・出力ファイルに含めない** — 受注情報・会員情報・顧客名等はログや出力ファイルに記録しない
- **破壊的コマンドは確認してから実行** — `rm -rf` や本番DBへの直接操作は必ず確認を取ってから
- **ファイル削除・上書き前の確認** — 既存ファイルの上書き・削除は事前に確認を取る
- **パスワードをチャットに出力しない**
- **Downloads直下・デスクトップ直下にファイルを作成しない**
- **外部URLへの自動アクセス禁止** — 明示的に指定されたURL以外は自動でアクセスしない

## HiBoardを触るときの必須ルール

作業場所は `C:\Users\<ユーザー名>\Projects\GITHUB_Production_Management`(自分のWindows PC内)。
**そのフォルダ内の `CLAUDE.md`(開発ルール・本番反映手順)を必ず読んでから作業すること。**

2. 実装後は自分のPCで動作確認まで行う

4. **本番への反映は久保田が行う。**三浦さんの担当はmainへpushするところまで。pushしたら必ず久保田へ連絡する
   (本番機は久保田が操作する。三浦さんのPCはサーバー機と切り分けられており、`update.bat` は実行できない)
