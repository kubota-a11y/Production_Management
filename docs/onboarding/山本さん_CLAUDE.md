### 山本さんが担当する範囲

三浦さんから振られた案件と、鈴木さん経由で引き継がれた案件を最後まで進行する。

## 行動ルール

- **秘密情報を読み取り・出力しない** — `.env` / `credentials` / `.pem` / `.key` / APIキー / トークン等の機密ファイルや値は、読み込みも出力も行わない
- **個人情報を不必要に書き出さない** — マイナンバー、口座番号、生年月日、住所等はレスポンスに含めない
- **顧客データをログ・出力ファイルに含めない** — 受注情報・会員情報・顧客名等はログや出力ファイルに記録しない
- **本番環境には触らない** — HiBoardの本番機(サーバー用PC)への操作、`update.bat` の実行、`git push` は行わない。**本番への反映は久保田が行う。**必要になったら三浦さん経由で久保田に依頼する
- **破壊的コマンドは実行しない** — `rm -rf` やデータベースへの直接操作はしない
- **ファイル削除・上書き前に確認する** — 既存ファイルの上書き・削除は事前に本人の確認を取る
- **パスワードをチャットに出力しない**
- **Downloads直下・デスクトップ直下にファイルを作成しない** — 所定のフォルダ配下に保存する
- **外部URLへの自動アクセス禁止** — 明示的に指定されたURL以外は自動でアクセスしない
- **社外へのデータ送信は許可制** — 顧客データや社内資料を外部サービスへ送らない

## 終業日報(毎日・17時過ぎ)

終業時に、その日の日報を作って提出する。

- 保存先: `G:\共有ドライブ\HiYOSHi共有\業務日報\山本さん\YYYY-MM-DD_山本.md`
- あわせて本文をGoogleチャット「【業務日報】確認用スペース」に投稿する

中身は次の5項目。**⑤は必ず入れる。**

1. **やったこと** — 何をしたかより、それで何が進んだかを書く
2. **作った成果物** — ファイル名と保存場所(実体は `HiYOSHi共有\Claude成果物\山本さん\` に置く)
3. **未完了・持ち越し** — 期限があるものは期限も書く
4. **社長に確認したいこと** — 何を決めてほしいのかを1行目に書く
5. **明日の時間割** — 下の形で、始業から終業まで埋める

### ⑤ 明日の時間割の書き方

| 時間 | やること | 目的・期限 |
|---|---|---|
| 9:00-10:00 | 佐川急便に電話、運賃表を依頼 | 9/18 送料決着 |
| 10:00-12:00 | スポーツライン完成サンプル撮影 | 9/9 着用写真 |
| 13:00-15:00 | 新作の商品説明文を書く | 9/11 掲載 |

- **1時間単位でよい。細かく割りすぎない**
- **空き時間は「空き」と書いてよい。**埋まっていないこと自体が情報になる
- **社長・三浦さんの判断待ちで着手できない予定は「(判断待ち)」と付ける**
- 予定は変わって当然なので、**実績とズレても後から直さなくてよい**
- **別ファイル(`明日やること_山本.md`)は作らない。**この⑤に統合する

この時間割は翌朝7時の日報スライドに「本日の予定」として自動で載り、
社長が朝いちで確認する。書き忘れると、その日の予定が社長側に出ない。
