# Claude Code セットアップ手順(三浦さん・山本さん)

久保田が本人と一緒に、最初の1回だけ実施する。所要 30〜45分。

---

## 事前準備(久保田)

1. **Team プラン(Standard シート × 2)を契約する**
2. 2人を招待する。招待先は**会社のメールアドレス**にする(個人Gmailは使わない)
   - 退職・異動時にアカウントを止められるようにするため
3. 本人にパスワードを設定してもらう。**パスワードは久保田が代わりに入力しない**

---

## 山本さん(最小構成)

山本さんの用途は「壁打ち・見積書作成・EC写真・HiBoardへの入力」で、
**HiBoardのソースコードを触る必要は当面ない**。リポジトリのcloneは省略する。

### 1. アプリを入れる

1. ブラウザで `claude.ai/download` を開き、**Windows版のClaudeデスクトップアプリ**をダウンロード
2. インストーラを実行
3. 起動して、招待メールで作ったアカウントでサインイン
4. 画面左下にアカウント名と `Team` の表示が出れば成功

### 2. 個人ルールを置く

`山本さん_CLAUDE.md` を、山本さんのPCの以下の場所に **`CLAUDE.md` という名前で**置く。

```text
C:\Users\<ユーザー名>\.claude\CLAUDE.md
```

`.claude` フォルダが無ければ新規作成する。

> **久保田の `~/.claude/CLAUDE.md` はコピーしないこと。**経営戦略・融資などの情報が入っている。

### 3. 動作確認

アプリのチャット欄に、そのまま打ってもらう。

```text
私の担当業務は何ですか？
```

CLAUDE.md の内容(見積書作成、EC写真、HiBoardへの入力、三浦さんの下)が返ってくれば設定できている。
返ってこない場合は置き場所か、ファイル名が `CLAUDE.md` になっているかを確認する。

### 4. 最初に使ってもらうこと

いきなり全部は渡さない。まずこの2つから。

- **壁打ち** — 「お客様への納期回答の文面を考えて」のような相談
- **資料の下書き** — 見積の内容整理、メール文面

慣れてきたら見積シミュレーターとの連携などを足す。

---

## 三浦さん(HiBoardの運用込み)

三浦さんはHiBoardの一次対応と本番反映を担当するため、リポジトリまで入れる。

### 1〜2. アプリと個人ルール

山本さんと同じ手順。置くファイルは **`三浦さん_CLAUDE.md`**。

### 3. Git とリポジトリ

1. Git for Windows を入れる(`git-scm.com`)
2. GitHubのアカウントを用意し、リポジトリへのアクセス権を久保田が付与する
3. 作業用フォルダを決めて clone する

```text
C:\Users\<ユーザー名>\Projects\
```

> **デスクトップ直下やGoogleドライブ同期フォルダには置かない。**
> ドライブが丸ごと同期してしまい、`node_modules` まで巻き込んで壊れる。

### 4. 権限設定を置く

`三浦さん_settings.local.json` を、cloneしたリポジトリの中に
**`.claude/settings.local.json`** という名前で置く。

このファイルは git 管理外なので、リポジトリを更新しても消えない。

### 5. 動作確認

Claude Code でリポジトリのフォルダを開き、こう聞いてもらう。

```text
このリポジトリの本番反映の手順を教えて
```

`CLAUDE.md` に書いてある「Macで確認 → mainへpush → 本番機で update.bat」の流れが
返ってくれば、リポジトリのルールを読めている。

### 6. 最初に使ってもらうこと

- **HiBoardの不具合の一次切り分け** — 症状を伝えて、設定・データ・コードのどれが原因かを絞る
- **週次「社内システムお知らせ」の作成**

本番反映は、最初の数回は久保田が横で見る。

---

## つまずいたときの確認先

| 症状 | 見るところ |
|---|---|
| サインインできない | 招待メールのリンクの有効期限。久保田が再送する |
| CLAUDE.md が効いていない | 置き場所とファイル名(`CLAUDE.md`、拡張子が `.md.txt` になっていないか) |
| `git push` が拒否される(山本さん) | **仕様どおり**。本番反映は三浦さんに依頼する |
| `.env` が読めないと言われる | **仕様どおり**。機密情報のため全員に対して禁止している |

---

## 運用開始後にやること(久保田)

- 1週間後に2人から使用感をヒアリングし、権限が厳しすぎる箇所を緩める
- `/usage` で2人の消費量を確認し、Standard シートで足りているかを見る
