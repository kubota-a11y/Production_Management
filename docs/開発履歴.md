### 常駐化でNSSMを却下した理由（重要な経緯）

Windowsサービス（NSSM）だと LocalSystem 権限で動くため**NASの割り当てドライブ（Z:）が見えず**、
デザインデータ閲覧・注文画像保存・NASバックアップの計4か所が壊れる。
同じ理由でタスクスケジューラでも `/rl highest` は付けない（管理者権限プロセスからも割り当てドライブが見えない）。

設定時のつまずき: PowerShell では `%USERNAME%` が展開されない（`$env:USERNAME` を使う）／
管理者でないと「アクセスが拒否されました」。→ 手順は `docs/Windowsサービス化手順.md` に反映済み。

## 納品後の履歴一元化・顧客台帳

### 納品後履歴の一元化（2026-07-29 `ad17ca5`）

Freee（見積/請求）・goodnote（指示書）・NAS（データ）に分かれる納品後履歴を、HiBoardの案件を入口に一元化。

1. `projects` に `freee_quote_url` / `freee_invoice_url` を追加。編集モーダルには「📄 開く」ボタン（https必須チェックあり）。
   **リピート複製には意図的に引き継がない**（新注文は新見積のため）
2. 納品履歴の「📁 フォルダ」を、既存 `/api/nas/list`・`/download` を流用したブラウザ内フォルダ閲覧モーダルに置き換え
3. 納品済みモーダルに「goodnoteの指示書PDFをNASフォルダに保存した」チェック（未チェックでも確認ダイアログを経て納品可＝例外許容）

あわせて運用ルール（社長承認済み）: 納品時に goodnote 指示書PDF＋Freee PDF を案件のNASフォルダへ保存。

### 顧客台帳 `/customers`（2026-07-29 `d81508b`）

顧客マスタは持たず `projects.customer_name` のTRIMグルーピングで一覧を自動生成（社内デザイン案件・空欄は除外、完全一致名寄せ）。

- 一覧: 案件数/納品済み/累計数量/初回受付/最終納品/加工種別/📝メモ有無
- 詳細: 顧客メモ（`customer_notes` テーブル・顧客名キーUPSERT）＋全案件履歴
- API: `GET /api/customers`、`GET /api/customers/projects?name=`、`GET/PUT /api/customer-notes`
- NASフォルダ閲覧モーダルは `js/nas-browse.js` に共有モジュール化し納品履歴と共用

**並び替え・絞り込み（`4ad6b75`）**: 取引案件数/取引数量/最終納品 × 多い順/少ない順、加工種別で絞り込み。
すべてクライアント側（`customers.js` の `filteredCustomers`→`sortCustomers`）。
最終納品が未納品の顧客は昇順・降順どちらでも末尾にまとめる。
比較関数は `compare=(av,bv)=>(av<bv?-1:1)*dir` の形（実装当初に符号を逆にして「多い順」が昇順になる不具合を出した箇所）。

### 案件詳細モーダル（2026-07-29 `4ad6b75`）

顧客台帳・納品履歴の**案件名クリック / 🔍 詳細**で開く。`GET /api/projects/:id/detail` が
案件情報・`case_items`（`catalog_json`/`matrix_json` をパースしてサイズ×カラー×枚数）・
プリント箇所・名簿件数・納品記録・**NASフォルダ内の書類**を返す。

- `collectCaseDocuments()` が案件フォルダを深さ2・走査600件/返却40件上限で走査し、拡張子（pdf/jpg/png/heic/webp）で絞り、

- UIは共有モジュール `js/case-detail.js`（CSSは `main.css` の `.case-detail-*`）
- 加工方法ラベルは注文フォーム（print/embroidery/both）と取引先フォーム（silk/dtf等）の両方に対応

## 2026-07-30 納品済み案件の準備項目が残り続ける問題を修正

### 症状

納品済みの案件なのに、準備項目のタスクがいつまでも残っていた(社長report)。

### 原因

`POST /api/projects/:id/deliver` は `case_time_allocations`(作業ブロック)は削除していたが、
**`case_preparation_items` は未完了のまま放置していた**。項目が「まだやること」として残るため、
`status != '完了'` を条件にしている次の3か所に永久に出続けていた。

1. **デザイナーのマイスケジュールボード「日付が未定のタスク」**(`lib/designer-board.js` の `unscheduled` クエリ)
   … 案件ステータスの条件が無く、納品済みでも本人のやることとして残り続ける。ここが一番影響が大きかった
2. **勤務時間編集モーダルの「準備項目タスクの割り当て」候補プルダウン**(`assignablePrepItems` の繰り越し分)
3. 週間ボードの準備項目リストの繰り越し … 表示は `PREP_LIST_HIDDEN_PROJECT_STATUSES` で除外されていたが、データは残っていた

### 対応(社長方針: 納品したものは未完了のタスクが残っていても全て完了とみなす)

- **納品時に未完了の準備項目をまとめて完了にする**(deliver のトランザクション内)。
  これで上記3か所すべてが同時に解決する(どれも `status != '完了'` で絞っているため)
- **既存データのバックフィル**(`db/init.js`、起動時1回・冪等)。
  納品済み案件に残っていた未完了項目を完了にする。`completed_at` は納品日を使う
- 保険として表示側にもガードを追加: 繰り越しAPI(`overdue_before`)と
  デザイナーボードの `unscheduled` から `p.status = 'COMPLETED'` を除外

`syncCaseStatusForPreparationItems()` は WAITING↔PREP_COMPLETE しか動かさないので、
完了にしても案件ステータスが COMPLETED から巻き戻ることはない(検証済み)。

### あわせて修正: 案件別消化率の表示がはみ出していた

`.sb-progress-item` の数値列が固定140px + `white-space: nowrap` で、
`2h / 10.0h（見積もり参考値）（20%）` が枠外に飛び出していた。

- 列幅を `minmax(0, 220px) minmax(80px, 1fr) auto` にして内容に合わせて伸ばす
- 「(見積もり参考値)」を **「参考値」バッジ**(title属性に説明)に変え、
  時間・パーセント・バッジを flex で並べて折り返せるようにした
- パーセントは等幅数字＋100%超で赤にして読みやすくした

### 2026-07-30 ヘッダーにデザイナーのボードへのリンクを追加 / 一覧の「作業担当者」列を削除

**デザイナーのマイスケジュールボードへのショートカット**(社長要望)

トークン付きURL(`/designer/{token}`)を覚えないと開けなかったので、社内用の

  (トークンは返さない)から取り、sessionStorageに覚えてページ移動時のちらつきを防ぐ。
  **毎回取得し直し、リンクが無効化・削除されたらキャッシュを捨てて既定ラベルに戻す**
  (別人の名前のままボードを開かせないため)

## 2026-08-03 紹介コード台帳(スプレッドシート)への自動記入

### 目的

社員がHiBoardを開かなくても「誰にどのコードをお渡ししたか」を引けるようにする。
紹介カードを書くとき・お客様から「私のコード何番だっけ?」と電話をもらったときに使う。

### 設計判断

- **トリガーは「発行時」のみ**(社長判断 2026-08-03)。紹介経由の受注が発生したときの実績記録は今回入れていない。
  必要になったら `lib/order-intake.js` 側に足す(受注候補の着地時に `referral_code` を見て台帳へ書く形になる)
- **保存先は社員TODOリストと同じブックの「紹介コード台帳」タブ**。既存のApps Scriptウェブアプリ・

- **台帳は2026-07-31に手運用用として先に作られていた**(Apps Scriptの `紹介コード台帳.gs` /
  `setupReferralLedger`)。**新規に作らず、その既存レイアウトへ追記する**形にした。
  列は A紹介コード / B紹介者名 / C種別 / D発行日 / Eカード渡し済 / F紹介先 / G成約日 /

- **台帳に載せるのは紹介者(コードをお渡しした方)の情報だけ**。ご紹介先のお客様の氏名は送らない

- **重複防止はシート側で行う**(B列のコードで判定)。HiBoard側に「送信済み」フラグを持たせると、
  シートを作り直したときに二度と送れなくなるため、状態はシートの内容そのものを正とした
