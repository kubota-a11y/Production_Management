# freee連携セットアップ手順(見積書の自動作成)

見積シミュレーター(`/quote-sim`)の「🧾 freeeに見積書を作成」を使うための初期設定。
**この作業は1回だけ**。以降は三浦さん・山本さんがボタンを押すだけで見積書が作れる。

作業するのは社長(freeeの管理者権限が要るため)。所要10分程度。

---

## 前提

- freee請求書を使っていること(今まで見積書を作っていた `invoice.secure.freee.co.jp` がそれ)
- 設定するPCでHiBoardが動いていること

---

## ステップ1: freeeでアプリを登録する

> **2026-08-21 実施済み**(有限会社HiYOSHi のアプリ「HiBoard」/ アプリID 83941)。
> 作り直すときだけこの手順をなぞる。

1. freeeにログインした状態で **[freeeアプリストア > アプリ管理](https://app.secure.freee.co.jp/developers/applications)** を開く
2. 「新規追加」でアプリを作る
   - アプリ名: `HiBoard`
   - 概要: `生産管理システムから見積書を作成する`
   - アプリタイプ: **プライベートアプリ**(社内利用。アプリストアには公開しない)
3. 基本情報タブの **コールバックURL** を次に変える(初期値の `urn:ietf:wg:oauth:2.0:oob` を置き換える)

   ```
   http://localhost:3000/api/freee/callback
   ```

   > ⚠️ このURLは**HiBoardが動いているPCのブラウザで認可作業をする**前提。
   > 開発機(Mac)でも本番機(Windows)でも同じURLが使えるので、アプリは1つで足りる。
   > 別のPCから認可したい場合は、本番機のLAN内IPを使い(例 `http://192.168.0.31:3000/api/freee/callback`)、
   > `.env` の `FREEE_REDIRECT_URI` にも同じ値を書くこと。**両方が完全に一致していないと認可が通らない。**

4. 「権限設定」タブで**次の3つだけ**を有効にして保存する(過剰な権限は付けない)

   | データ種別 | 参照 | 更新 | 用途 |
   | --- | :---: | :---: | --- |
   | [freee請求書] 全帳票種別 | ✅ | ✅ | 見積書の作成 |
   | [会計] 取引先 | ✅ | — | 取引先を名前で検索する |
   | [会計] 事業所 | ✅ | — | 事業所IDの自動判定 |

   > 取引先の「更新」は付けない。**取引先マスタはHiBoardから触らない方針**のため。

5. 基本情報タブに表示される **Client ID** と **Client Secret** を控える

## ステップ2: `.env` に書く

HiBoardが動いているPCの `.env`(本番機は `C:\Production_Management_v2\.env`)に追記する。

```
FREEE_CLIENT_ID=(ステップ1のClient ID)
FREEE_CLIENT_SECRET=(ステップ1のClient Secret)
# 本番機以外のPCから認可する場合だけ、ステップ1と同じURLを書く
# FREEE_REDIRECT_URI=http://192.168.0.31:3000/api/freee/callback
```

> **事業所IDの指定は要らない。** 認可後にfreeeから自動で取得する
> (事業所IDはfreeeの画面に出てこない値なので、探させない作りにしている)。
> 事業所が2つ以上ある場合だけ画面にエラーが出るので、そのときは
> メッセージに出るIDを `FREEE_COMPANY_ID=` で指定する。

書いたらサーバーを再起動する(本番機はタスクスケジューラ方式なので、
`node` のウィンドウを閉じれば5秒後に自動で立ち上がり直す)。

## ステップ3: freeeと連携する(認可)

1. そのPCのブラウザで見積シミュレーターを開く
2. 「🧾 freeeに見積書を作成」を押す → 連携を促す確認が出るので **OK**
3. freeeのログイン画面が開くので、ログインして **許可** を押す
   - ★ パスワードはfreeeの画面にだけ入力する。HiBoardがパスワードを預かることはない
4. 「freeeとの連携が完了しました」と出れば終わり

## 運用上の注意

### 90日ごとに再認可が必要になることがある

freeeのリフレッシュトークンは**発行から90日**で切れる。
サーバーが動き続けていれば自動で更新されるので普段は意識しなくてよいが、
**本番機を90日以上止めていた場合は再認可が必要**。
その場合は画面に「freeeと未連携です」と出るので、ステップ3をやり直す。

### 認証情報の置き場所

- Client ID / Secret … そのPCの `.env`(git管理外)
- アクセストークン … そのPCの `data/freee-token.json`(git管理外・DBには入れない)

DBのバックアップにトークンが混ざらないよう、あえてDBの外に置いている。
**この2つはコピーして持ち出さないこと。**

### うまくいかないとき

| 症状 | 原因と対処 |
| --- | --- |
| 「freee連携が未設定です」 | `.env` の2項目が入っていない、またはサーバー未再起動 |
| 認可画面で「リダイレクトURIが一致しません」 | ステップ1のコールバックURLと `.env` の `FREEE_REDIRECT_URI` が違う |
| 「取引先を取得できませんでした」 | アプリの権限設定で [会計] 取引先 の参照が入っていない |
| 「事業所が複数あります」 | メッセージに出るIDを `.env` の `FREEE_COMPANY_ID` に書く |
| 「事業所を取得できませんでした」 | アプリの権限設定で [会計] 事業所 の参照が入っていない |
| 発行時に「金額が合いません」 | 明細の積み上げと合計がずれている。シミュレーターの入力を確認する(安全のため発行を止めている) |
